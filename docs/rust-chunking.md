# Rust chunking

The Rust reader (`src/shared/readers/rust_reader.py`, extension `.rs`) parses
files with the tree-sitter `rust` grammar from `tree-sitter-language-pack`,
which is already a dependency. It runs on CPU and needs no network access.

Rust has no classes. The reader maps Rust items onto the chunk types of the
Java, C#, Go and PHP readers ([csharp-go-php-python-chunking.md](csharp-go-php-python-chunking.md)),
so the reranker treats them the same way.

`.rs` files are indexed only when a `SOURCE_DIRS` entry lists `.rs` in its
`extensions`. Existing configs are not affected.

## Context prefix

Every chunk starts with a header:

```
// File: mod.rs
// Module: tests::helpers
// Class: impl<'s, M: Matcher> Searcher<'s, M>
```

- `// Module:` appears inside inline `mod` blocks and gives the path from
  the file, for example `tests::helpers`. A file-level module has no
  `// Module:` line.
- `// Class:` carries the `impl` header for items in an impl block, and the
  trait header for trait default methods.

`unit_name` is the file stem. Chunks inside inline modules also carry
`module_path`.

## Node types

| Rust item | Node type | Notes |
|---|---|---|
| `struct`, `enum`, `union` | `class_summary` | The doc comment, attributes and full declaration, then the member signatures of every `impl` of the type in the same file, one block per impl header. Large types also get a `class_overview` that lists fields or variants, methods and traits (implemented and `#[derive]`d). |
| `trait` | `class_summary` | The header and the signatures of the associated functions, types and constants. Blanket impls (`impl<T: X> Trait for T`) are listed under the trait. |
| `impl` of a type not declared in the file | `class_summary` | The impl header and its member signatures. `rust_kind` is `impl`. |
| function, method, trait default method | `method_declaration` | `function_name`; `class_name` is the impl type or the trait; `impl_trait` for trait impls; `is_async` for `async fn`. |
| `new` / `new_*` in an inherent impl returning `Self` or the type | `constructor_declaration` | |
| `type` alias, associated type | `type_alias_declaration` | |
| `const`, associated const | `constant_declaration` | |
| `static` | `field_declaration` | |
| `macro_rules!` | `macro_definition` | |
| item-level macro call (`thread_local!`, `lazy_static!`, test macros) | `macro_invocation` | `macro_name`; `object_name` is the first identifier argument (`rgtest!(name, ...)`) or the `static` it declares. |
| three or more short calls of the same macro in a row | `macro_group` | `symbols` lists the first-argument names; `group_count`. |
| `extern "C" { ... }` | `extern_block` | `symbols` lists the declared functions. |
| `use`, `extern crate`, `mod name;` | `import_group` | One per module. |
| inline `mod name { ... }` | `module_summary` | Lists the items of the module (at most 60 lines); its items are chunked as usual. |
| `//!` module docs, long free comments | `block_comment` | Module docs carry `rust_kind: module_doc`. |
| three or more short methods of one type in a row | `method_group` | As in the other readers. |

`///` and `/** */` doc comments, plain comments and `#[...]` attributes
directly above an item, with no blank line between, are part of the item's
chunk. A `#[cfg(...)]` on the item or on an enclosing `mod` or `impl` is stored
as `cfg` metadata. Several conditions are joined with `&&`, for example
`unix && target_os = "linux"`.

## Symbols

`object_name` holds the declared name, which the exact symbol lookup
(`SYMBOL_LOOKUP_K`) matches. A chunk that declares several names lists them
all in `symbols`:

- a type summary lists the type, its enum variants and its methods;
- a trait summary lists the trait and its associated items;
- a module summary lists the module and its items;
- method groups, macro groups and extern blocks list their members.

`SYMBOLS_PER_SPLIT_PART` and `SYMBOLS_MAX_PER_CHUNK` apply to these lists in
the same way as for C/C++ ([configuration.md](configuration.md)).

## Rerank profile

The `rust` profile is active when an index lists `.rs`. It provides:

- `Name.rs` file-stem targets;
- test paths: `benches/`, `tests.rs`, `*_test.rs`, `*_tests.rs`, plus the core
  `tests/` rule;
- binding paths: `ffi/`, `sys/`, `*-sys/` crates;
- declaration names for `const` / `static`, `macro_rules!` and `mod`. The core
  rules already cover `fn`, `struct`, `enum`, `trait`, `type` and `union`;
- detail types `macro_definition`, `macro_invocation`, `macro_group` and
  `extern_block`;
- `module_summary` as a secondary overview type.

## Limits and known gaps

- Items generated by macros (derive output, `macro_rules!` expansions) are not
  visible to the reader.
- A type summary lists only the impls in the same file. Impls in other files
  are still indexed as method chunks with `class_name` set to the type.
- Test code inside `#[cfg(test)] mod tests` sits in the same file as the code
  it tests, so the test-path demotion does not apply to it. Its chunks carry
  `cfg: test`.
- Tree-sitter recovers from syntax errors: the valid items of a broken file
  are still chunked. A file that yields no chunk is indexed as `full_file`.
